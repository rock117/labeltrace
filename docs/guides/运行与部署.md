# 运行与部署

面向开发与运维的启动说明。产品操作流程见 [数据集从上传到发版](./数据集从上传到发版.md)；任务队列细节见 [docs/jobs.md](../jobs.md)。

## 架构速览（P0）

| 组件 | 作用 |
|------|------|
| **web** | React 静态资源 + nginx 反代 `/api` |
| **api** | FastAPI；同进程内跑 **PG 任务消费者**（抽帧等，镜像含 ffmpeg） |
| **postgres** | 元数据 + `jobs` 队列（`JOB_BACKEND=pg`） |
| **blob** | 默认绑定 `./backend/data/blobs` ↔ 容器 `/data/blobs`（宿主机与 Docker 共用） |

P0 **不**部署独立 worker、**不**使用 Redis。

鉴权：注册/登录后 Bearer JWT（见登录页）。

### 两种运行方式（都保留）

| 方式 | 适用 | 怎么用 |
|------|------|--------|
| **Docker Compose 全套** | 服务器部署、验收演示、一键环境 | `docker compose up -d --build`（下文） |
| **宿主机 api/web + Docker 仅 PG** | 日常改代码、热重载 | `scripts/dev-db.ps1` + `dev-api.ps1` + `dev-web.ps1` |

部署到服务器仍以 **Docker Compose** 为准；本地开发两种都可用，互不替代。

## 一键启动（Docker Compose · 部署 / 演示）

本机或服务器安装 **Docker**（含 Compose）即可。

基础镜像策略：**本地有就用本地**（`pull_policy: missing` / build `pull: false`）；没有则经国内镜像站拉取并打成官方短名。

```bash
# 仓库根目录
# Windows
powershell -File scripts/ensure-base-images.ps1
# Linux / macOS
# bash scripts/ensure-base-images.sh

docker compose up -d --build
```

### 改代码要不要每次 build？

默认 compose 把代码 **打进镜像**，所以改业务代码要 `--build`。网络不好时可用开发覆盖（**挂载源码 + 热重载**）：

```bash
# 首次仍建议先确保 api 镜像存在（依赖已装进镜像）
docker compose build api

# 日常开发：挂载代码，一般不用再 build
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
```

| 你改了什么 | 做什么 |
|------------|--------|
| `backend/app`、`alembic` | 保存即可（api `--reload`）；不行再 `restart api` |
| `frontend/src` 等 | Vite 热更新；不行再 `restart web` |
| `requirements.txt` / `Dockerfile` | 才需要 `docker compose build api` |
| `package.json` 依赖 | 删卷或 `docker compose ... run web npm ci` 后再起，或 rebuild |

只重启、不 build：

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml restart api
# 或
docker compose restart api
```

> 正式验收/演示仍用默认 `docker compose up -d --build`（nginx 静态产物）。

默认依次尝试（推荐首项 DaoCloud 完整前缀）：
`m.daocloud.io/docker.io/library` → `docker.m.daocloud.io/library` → `dockerproxy.net` / `1ms` / `rat` / `xuanyuan`。可覆盖：

```powershell
$env:DOCKER_MIRRORS = "m.daocloud.io/docker.io/library,dockerproxy.net/library"
powershell -File scripts/ensure-base-images.ps1
```

也可在 Docker Desktop → Docker Engine 配置 `registry-mirrors`（对官方短名 `docker pull` 生效）。构建时 apt / pip / npm 走国内源（阿里云 / 清华 / npmmirror）。
| 服务 | 地址 |
|------|------|
| **Web UI** | http://127.0.0.1:38471 |
| API（调试 /docs） | http://127.0.0.1:8001/docs |
| Postgres | 宿主机 `127.0.0.1:5433` → 容器 5432（用户/密码/库：`postgres` / `postgres` / `labeltrace`） |

常用命令：

```bash
docker compose ps
docker compose logs -f api
docker compose down          # 停服务（保留数据卷）
docker compose down -v       # 停服务并删除 pgdata / blobs（慎用）
```

冒烟路径：打开 Web → 创建项目 → 上传视频 → 抽帧审查 → 入集 → 标注 → 发版。

## 环境变量（API）

Compose 已内置默认值；覆盖时可在 `docker-compose.yml` 或 `.env`（Compose 变量）中修改。

| 变量 | 默认 / 说明 |
|------|-------------|
| `DATABASE_URL` | Compose：`postgresql+psycopg2://postgres:postgres@postgres:5432/labeltrace` |
| `BLOB_BACKEND` | `local`（默认）或 `s3` |
| `BLOB_LOCAL_ROOT` | Compose：`/data/blobs` |
| `BLOB_S3_*` | `BLOB_BACKEND=s3` 时使用（可对接 MinIO） |
| `JOB_BACKEND` | P0 固定 `pg` |
| `JOB_POLL_INTERVAL_SEC` | 默认 `0.5` |
| `JOB_LEASE_SEC` | 默认 `300` |
| `LOG_LEVEL` | 如 `INFO` |

切换默认写入后端后，**旧文件仍按 Asset 上记录的 `storage_backend` 读取**。

## 宿主机热重载（日常开发 · 与 Docker 部署并存）

改代码即时生效，不必每次 `docker build`。依赖：Python 3.11+、Node 20+、**ffmpeg 在 PATH**；Docker **只**跑 Postgres。服务器部署请仍用上一节全套 Compose。

```powershell
# 1) 停掉容器里的 api/web，只留 postgres
powershell -File scripts/dev-db.ps1

# 2) 终端 A：API
powershell -File scripts/dev-api.ps1

# 3) 终端 B：前端
powershell -File scripts/dev-web.ps1
```

| 地址 | 说明 |
|------|------|
| http://127.0.0.1:5173 | 开发 UI（Vite，`/api` → `8001`） |
| http://127.0.0.1:8001/docs | API |
| `127.0.0.1:5433` | Postgres（compose 映射；避开本机常见 5432） |

首次会自动建 venv / `npm install`；`backend/.env` 见 `.env.example`（含密码与 5433）。

手动等价命令：

```bash
docker compose up -d postgres
# backend
cd backend && python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
.\.venv\Scripts\alembic upgrade head
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
# frontend
cd frontend && npm install && npm run dev
```

验收/演示仍可用全套 Compose（见上文 `up -d --build`）。

## 日后扩展（不阻塞 P0）

- 拆独立 **worker** 容器：仍可 `JOB_BACKEND=pg`，api 只入队；见 `docs/jobs.md`。  
- 队列压力大再考虑 `JOB_BACKEND=redis`（需实现后配置）。  
- 可选增加 MinIO 服务作对象存储。

## 常见问题

| 现象 | 处理 |
|------|------|
| `compose up` 构建失败 | 先跑 `scripts/ensure-base-images.*`；确认 Docker Desktop 在跑；必要时换 `DOCKER_MIRROR` |
| 拉基础镜像超时 | 默认 DaoCloud；也可在 Docker Desktop → Registry mirrors 配国内加速，或改 `DOCKER_MIRROR` |
| Web 能开但接口失败 | `docker compose logs -f api`；确认 api healthy；浏览器访问 `/health` |
| 抽帧失败 | api 镜像已含 ffmpeg；看日志中的 `job_id` |
| 401 未登录 | 先打开登录页注册/登录 |
| 403 权限不足 | 须为项目成员；`viewer` 不能上传；发版/管成员仅 **owner**；邀请用对方已注册用户名 |
| Web `port already allocated` | 开发覆盖须用 `ports: !override`（已配置）；仍失败则 `docker rm -f labeltrace-web-1` 后重试 |
| 宿主机 API：`password authentication failed` | 本机常另有 PG 占 **5432**；LabelTrace Compose 映射为 **5433**，`.env` 用 `postgres:postgres@127.0.0.1:5433/labeltrace` |
| 视频/缩略图加载失败（元数据有、画面无） | 文件在 Docker 卷而宿主机 API 读 `./backend/data/blobs`；已改为绑定目录。旧数据可从卷拷入该目录后重启 API |
| 数据要清空重来 | `docker compose down -v`（会删 pg 卷；blob 在 `backend/data/blobs` 需手动删） |
