# 数据集：从上传到发版（操作说明）

面向使用者的短流程说明。系统行为契约以 OpenSpec（`openspec/changes/bootstrap-labeltrace-platform/specs/`）为准；本文不替代验收规格。

**本项目特点：** 甲方素材以**拍摄视频**为主，很少直接给图片。平台主路径是 **视频 → 抽帧 → 在帧上标注 → 发版导出**。

## 概念（先分清）

| 概念 | 作用 |
|------|------|
| **视频（video）** | 甲方交付的源文件；目录里主要看到它 |
| **帧（frame）** | 从视频抽出的图；入集、画框、进版本/导出的主要单位 |
| 图片（image） | 直接上传的图，或 YOLO 包导入的图；**可与帧混在同一数据集** |
| 素材库 / 目录 | 归档浏览（视频为主入口；帧多在视频详情里） |
| 标签 | 跨目录筛选（可打在视频上） |
| 数据集工作区 | 当前成员（多为 frame）与标注；可一直改 |
| 版本 | 只读快照；训练请用版本导出 |

**规则：** 不在整段视频上画 YOLO 框；已发版本不能改，更新 = 改工作区再发新版。

---

## 主路径：视频 → 抽帧 → 入集 → 标注 → 发版

1. **上传视频**到素材库某目录。  
2. **抽帧并设置参数**（每隔 N 帧 / 每隔 T 秒）→ 生成**候选帧**（落盘）。  
3. **人工审查**：候选帧按**出现时间顺序**排列（并显示帧号/时间），沿时间线浏览，**批量删掉**模糊、重复、无目标等不需要的帧（通常会删很多）。  
4. **创建数据集**（类别等；P0 为检测框）。  
5. **加入成员**：把该次任务里**留下来的帧**加入数据集（可全选剩余 / 再勾选）。  
6. 数据集详情看**来源摘要**（抽帧设置与保留数量 / 上传图 / 导入等）。  
7. **标注台**画框；每张须点 **提交**（`submitted`）。  
8. **发版**（全部成员都已提交后才能发；未标完会被拒绝）→ 导出 YOLO。  
9. 已发版本可在「版本」页 **查看快照**（只读）；工作区标注台仍是实时可编辑数据。  
10. 在快照或版本列表可 **应用到工作区**：把该版本成员与标注**合并**进当前工作区（同图覆盖标注并变为草稿；快照有而工作区没有的图会入集；工作区多出的图保留）。  
11. 数据集可将成员 **移出**（只删引用，不删素材库文件）。

可同时把**素材库上传的图片**加进同一数据集。  

**注意：** 抽帧 ≠ 自动入集；审查剔除发生在入集之前（已入集的帧要先移出集才能硬删）。

---

## 辅路径：已有 YOLO 图片包

导入 zip → 图成员（origin=import）→ 可与抽帧/上传图共存于同一集 → 发版。  

---

## 数据来源在数据集里怎么记

| 层级 | 记什么 |
|------|--------|
| 每一张成员 | Asset 上的 `media_kind`、`origin`；帧另有**源视频**、**原视频第几帧（frame_index）**、抽帧任务；上传图有目录/文件名；导入有 `import_id` |
| 数据集详情 | 聚合摘要 `memberSources`（抽帧 / 上传 / 导入各多少、抽帧参数等） |
| 已发版本 | 快照里带上来源摘要，可复现当时构成 |

---

## 更新已有数据集（又拍了新视频）

1. 上传新视频 → 抽帧。  
2. 打开原数据集 → 把新视频的帧**追加**进去。  
3. 只标新帧（或未标帧）。  
4. 发布 **新版本**（如 v1.1）；旧版本不变。

---

## 常见问题

**问：为什么不能直接在视频时间轴上标？**  
P0 先抽成帧再标，好接 YOLO 与版本；完整时间轴 UI 后续再做。

**问：帧会不会把素材库撑爆？**  
目录浏览以视频为主；帧挂在视频下，避免海量缩略图刷屏。

**问：训练导出的是视频还是图？**  
导出的是**帧图 + 标签**（YOLO detect）；血缘里仍能追回源视频。
