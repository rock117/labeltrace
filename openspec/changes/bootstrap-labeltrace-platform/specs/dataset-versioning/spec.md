# Spec Delta

## Purpose

提供数据集不可变版本：冻结素材引用、标注、类别与划分，支持相对父版本的变更摘要，以及按版本导出 YOLO 包。

## ADDED Requirements

### Requirement: 发布不可变版本
系统 MUST 能将数据集当前工作区（成员引用、划分、类别名、工作标注）发布为只读版本；发布后不得修改该版本快照内容。

#### Scenario: 成功发版
- **GIVEN** 数据集至少有一名成员，且每一名成员的工作标注状态均为 `submitted`
- **WHEN** 用户对数据集发布版本并指定版本名
- **THEN** 系统创建只读版本，快照包含当时的类别、成员、划分与标注

#### Scenario: 禁止改写已发布版本
- **WHEN** 客户端尝试修改已发布版本中的标注快照
- **THEN** 系统拒绝该请求

### Requirement: 未完成标注不得发版
系统 MUST 拒绝在「成员未全部提交标注」时发版。判定：数据集须至少有一名成员；每一名成员 MUST 存在对应工作标注且 `status = submitted`（仅有 `draft`、无标注记录或空成员集均不可发版）。

#### Scenario: 仍有未提交成员时发版失败
- **GIVEN** 数据集有成员，其中至少一名标注状态不是 `submitted`（含尚无标注记录）
- **WHEN** 用户尝试发布版本
- **THEN** 系统拒绝发版并说明尚有未提交标注的成员数量（或等价信息）

#### Scenario: 无成员时发版失败
- **WHEN** 用户对空数据集（无成员）尝试发版
- **THEN** 系统拒绝发版

### Requirement: 只读浏览已发版本
系统 SHALL 支持按版本标识打开该版本快照进行只读浏览（成员列表与当时标注）；浏览 MUST NOT 修改该版本或当前工作区标注。工作区标注台与版本浏览 MUST 在产品上可区分（如路由/徽章标明「工作区·可编辑」与「版本·只读」）。

#### Scenario: 打开版本快照
- **WHEN** 用户打开已发布版本 `v1.0` 的浏览视图
- **THEN** 系统展示该版本快照中的成员与标注，且界面标明只读，不可保存/提交到该版本

#### Scenario: 版本浏览不改工作区
- **GIVEN** 用户正在只读浏览版本 `v1.0`
- **WHEN** 其后打开同一数据集的工作区标注台（未执行应用到工作区）
- **THEN** 工作区仍为当前实时标注，不受版本浏览影响

### Requirement: 版本合并应用到工作区
系统 SHALL 支持将某已发版本快照**合并**到其所属数据集的工作区（产品文案可用「应用到工作区」）。合并规则：
- 快照中的素材若已是工作区成员：覆盖该 `(dataset, asset)` 的工作标注（含 shapes；状态置为 `draft` 以便继续编辑）；
- 若尚不是成员：加入成员（沿用快照中的 split，缺省则为 `unassigned`）并写入对应工作标注；
- 仅存在于工作区、不在该快照中的成员：MUST 保留不动；
- MUST NOT 修改该版本快照本身。

#### Scenario: 同图覆盖标注
- **GIVEN** 工作区与版本 `v1.0` 均含素材 X，且工作区标注与快照不同
- **WHEN** 用户将 `v1.0` 应用到工作区
- **THEN** 素材 X 的工作标注变为快照中的 shapes，状态为 `draft`，且 `v1.0` 快照不变

#### Scenario: 快照多出的图加入工作区
- **GIVEN** 版本 `v1.0` 含素材 Y，工作区当前不是成员
- **WHEN** 用户将 `v1.0` 应用到工作区
- **THEN** Y 成为工作区成员并带有快照中的标注

#### Scenario: 工作区多出的图保留
- **GIVEN** 工作区含素材 Z，版本 `v1.0` 不含 Z
- **WHEN** 用户将 `v1.0` 应用到工作区
- **THEN** Z 仍为工作区成员，其标注不被该操作清除

### Requirement: 父版本与变更摘要
系统 SHALL 允许新版本指定父版本，并 MUST 提供相对父版本的变更摘要（至少包含新增成员、移除成员、标注变更的计数或等价信息）。

#### Scenario: 相对父版本的摘要
- **WHEN** 用户基于父版本 `v1.2` 发布 `v1.3`，且工作区相对父版有增删与改标
- **THEN** 版本详情中可获得相对 `v1.2` 的变更摘要

### Requirement: 工作区与版本分离
发版后对工作区成员或标注的修改 MUST NOT 改变已发布版本的快照内容。

#### Scenario: 发版后改标不影响旧版
- **WHEN** 版本 `v1.3` 已发布，随后用户修改工作区中某素材的标注
- **THEN** 再次读取 `v1.3` 快照时仍为发版当时的标注

#### Scenario: 发版后追加成员再发新版
- **GIVEN** 数据集已发布版本 `v1.0`
- **WHEN** 用户向工作区追加新素材成员、完成标注后，以 `v1.0` 为父版本发布 `v1.1`
- **THEN** 系统创建只读版本 `v1.1`，其快照包含新增成员与最新标注，且 `v1.0` 快照内容保持不变
- **AND** `v1.1` 相对 `v1.0` 的变更摘要能反映成员新增（或等价信息）

### Requirement: 按版本导出 YOLO
系统 SHALL 支持按指定版本导出 YOLO 检测格式包（图像、对应 labels、以及含 names 的配置），导出内容 MUST 与该版本快照一致。

#### Scenario: 导出与快照一致
- **WHEN** 用户导出版本 `v1.3`
- **THEN** 导出包中的类别名、划分与标注与 `v1.3` 快照一致，且不依赖之后的工作区变更
