# Spec Delta

## Purpose

管理数据集：引用项目内共享素材、启用项目类别词表中的子集，以及 train/val/test 划分。加入数据集时不拷贝图片二进制。

## ADDED Requirements

### Requirement: 创建数据集
系统 SHALL 允许在项目内仅凭名称创建数据集。创建完成时 MUST 启用当时项目词表的全部已有类别；词表为空则启用列表为空。类别身份属于项目词表（见 project-workspace），不在创建数据集时新建。之后在项目中新建的类别 MUST 进入该项目每个数据集的启用集合。工作区勾选只表示用或不用，不向用户呈现编号。发版时才生成 `0..n-1`：手建类别按加入本数据集的先后，YOLO 导入按包内名字顺序。标注几何引用项目类别的稳定 `classId`。系统 SHALL 记录该数据集启用的标注类型集合（创建默认 `["rect"]`；有写权限成员可增删已注册类型，至少保留一类；停用某类型时若工作区标注仍含该 type MUST 拒绝）。YOLO zip 导入可按包内名字复用或新建项目类别，并按包内顺序写入目标数据集（替换该数据集原先的启用列表）；导入/导出按任务剖面选择 codec（见 dataset-import / dataset-versioning）。

#### Scenario: 创建数据集默认启用已有类别
- **WHEN** 项目已有类别 `划痕`、`污渍`，用户只提交名称创建数据集 `缺陷检测`
- **THEN** 数据集创建成功，启用这两类，启用标注类型默认包含 `rect`

#### Scenario: 项目尚无类别时创建数据集
- **WHEN** 项目词表为空，用户只提交名称创建数据集
- **THEN** 数据集创建成功，启用列表为空

#### Scenario: 启用多种标注类型
- **WHEN** 用户将数据集启用类型设为 `rect` 与 `polygon`
- **THEN** 读回包含二者；标注台仅出现对应工具

#### Scenario: 停用仍被引用的类型失败
- **WHEN** 工作区标注仍含 `polygon` 项，用户试图从启用集去掉 polygon
- **THEN** 系统拒绝

#### Scenario: 读取启用的标注类型
- **WHEN** 用户获取数据集详情
- **THEN** 响应包含 `enabledAnnotationTypes`（或等价字段）与已启用类别列表（含项目类别 id、name、顺序、颜色）

### Requirement: 数据集启用项目类别
系统 SHALL 默认在数据集上启用项目词表中的类别，并允许有写权限的成员取消不需要的类别或重新勾选。勾选不表示顺序。启用列表中的 id MUST 属于该数据集所在项目。同一项目类别可被多个数据集启用。取消某类别时，若本数据集工作区标注仍引用其 `classId`，MUST 拒绝。改名发生在项目词表上，未发版工作区显示新名称；已发版本快照中的名称与编号不受影响。尚无启用类别时，标注台 MUST NOT 允许画框。

#### Scenario: 取消不需要的类别
- **WHEN** 数据集已启用 `划痕`、`污渍`，用户取消 `污渍`
- **THEN** 启用集合只保留 `划痕`

#### Scenario: 无类别时不能画框
- **WHEN** 用户打开尚未启用类别的数据集标注台
- **THEN** 界面不提供可落笔的类别，并说明先在 YOLO类别页创建

#### Scenario: 改名不打乱已标
- **WHEN** 用户在项目词表将类别 `划痕` 改名为 `划痕-A`，且某数据集已有框引用该类别 id
- **THEN** 框仍绑定同一 `classId`，该数据集显示名变为 `划痕-A`

#### Scenario: 停用仍被引用的类别被拒
- **WHEN** 用户从数据集启用列表去掉某类别，但本数据集至少有一个框的 `classId` 指向它
- **THEN** 系统拒绝停用

### Requirement: 重命名数据集
系统 SHALL 允许有写权限的成员更新数据集名称。重命名 MUST NOT 改写已发布版本快照内容。

#### Scenario: 重命名数据集
- **WHEN** 用户将数据集名称改为新名称
- **THEN** 工作区数据集名称更新；已发版本记录保持发版时快照不变

### Requirement: 引用素材不拷贝
系统 SHALL 允许将已有项目素材以引用方式加入数据集，加入时 MUST NOT 复制素材二进制。成员可为上传的图片（`image`）或视频抽帧（`frame`），同一数据集允许混合来源。

#### Scenario: 从素材库加入上传图片
- **WHEN** 用户将素材库中上传的图片加入某数据集
- **THEN** 这些图片成为数据集成员，并仍保留在原目录

### Requirement: 上传入口仅在素材库
产品 UI MUST 将文件上传（图片/视频）放在素材库；数据集页 MUST NOT 提供直接选择本地文件上传入集的入口（避免双入口混乱）。入集路径为：素材库已有素材勾选加入，或抽帧审查后入集。

#### Scenario: 数据集页无本地上传控件
- **WHEN** 用户打开数据集工作区页
- **THEN** 界面不提供「选择本地文件上传到数据集」的入口；引导至素材库或从库勾选

#### Scenario: 向已有成员的数据集追加素材
- **GIVEN** 数据集已有若干成员（可已发过版本）
- **WHEN** 用户再次从素材库将新选中的素材加入该数据集
- **THEN** 新素材成为成员，原有成员与其工作区标注仍保留

#### Scenario: 同一数据集混合抽帧与上传图
- **WHEN** 用户将某次抽帧得到的 frame 与若干上传的 image 一并加入同一数据集
- **THEN** 两类成员均出现在成员列表中，且可分别追溯其来源类型

### Requirement: 按抽帧任务批量入集
系统 SHALL 支持将一次或多次抽帧任务中审查后仍保留的 frame 加入数据集（按 `extract_job_id` 批次入集，不要求把 frame 摊平进素材库目录）。产品 UI SHALL 列出项目内可入集的抽帧任务并支持多选后批量加入，MUST NOT 仅依赖「最近一次抽帧」隐式入集。

#### Scenario: 多视频抽帧任务一并入集
- **WHEN** 项目中多个视频各自完成抽帧与审查，用户在数据集页勾选这些抽帧任务并确认加入
- **THEN** 各任务剩余 frame 均成为该数据集成员，来源摘要能区分不同源视频/任务

#### Scenario: 追加另一视频的抽帧任务
- **GIVEN** 数据集已含某视频抽帧成员
- **WHEN** 用户再勾选另一视频的抽帧任务加入
- **THEN** 新任务帧追加为成员，原有成员与标注保留

#### Scenario: 数据集成员可见原视频帧号
- **WHEN** 用户查看含抽帧成员的数据集成员列表（或成员详情）
- **THEN** 对每个 frame 成员可获知源视频标识以及其在原视频中的帧序号（`frame_index` 或等价时间位置）

#### Scenario: 同一素材进入两个数据集
- **WHEN** 同一素材被加入数据集 A 与数据集 B
- **THEN** 两个数据集均引用同一素材标识

### Requirement: 成员任务分配
系统 SHALL 允许将数据集成员分配给项目内可写成员（`owner` / `annotator`）。每个成员至多一名 `assignee`；`assignee` 为空表示未分配。不新增角色。

- **入集默认**：新加入数据集的成员 MUST 默认将 `assignee` 设为一名项目 `owner`（优先为当前操作者若其为 owner，否则取该项目一名 owner），以免负责人再手动「全部分给自己」。清空分配后仍可为未分配。
- **改分配**：仅 `owner` 可单条或批量指定/清空 `assignee`。
- **可见性**：`owner`（及只读 `viewer`）可列出全部成员；仅有 `annotator`、无 `owner` 的成员列出时 MUST 只看到分给自己的成员。
- **未分配**：非 `owner` 不得对未分配成员写入标注。
- **转单**：将原分给 C 的成员改分给 A 后，A 的列表合并为一份（无独立「任务包」实体）；C 不再看到这些成员。
- **发版**：P0 仍要求数据集**全部**成员均已 `submitted`（含未分配），分配不改变发版门槛。

产品 UI：数据集页供 owner 多选成员后批量分配；标注台 owner 可切换「只看我的 / 全部」，annotator 默认只看自己的。

#### Scenario: 入集默认分给负责人
- **WHEN** owner 将素材加入数据集
- **THEN** 新成员的 `assignee` 为该 owner（或项目内一名 owner），无需再点分配

#### Scenario: 批量分配给标注员
- **WHEN** owner 将 50 名成员批量指定给用户甲
- **THEN** 这 50 名成员的 `assignee` 为甲；甲在标注台默认只看到这些成员

#### Scenario: 标注员看不到他人名下成员
- **WHEN** 仅有 annotator 角色的用户乙列出数据集成员
- **THEN** 列表不含分给他人或未分配的成员

#### Scenario: 转单合并列表
- **GIVEN** 用户甲已完成自己的分配，owner 将原分给丙的成员改分给甲
- **WHEN** 甲打开标注台（只看我的）
- **THEN** 列表包含甲原有成员与新转入成员，且无单独的第二任务包

#### Scenario: 未分配不可由标注员标注
- **WHEN** 仅有 annotator 角色的用户对未分配成员写入标注
- **THEN** 系统拒绝

### Requirement: 移除数据集成员
系统 SHALL 允许通过删除引用将素材移出数据集，且 MUST NOT 因移除引用而硬删除素材实体或其对象文件。产品 UI SHALL 支持多选成员后批量移出。

#### Scenario: 从数据集移除
- **WHEN** 用户从数据集中移除某素材
- **THEN** 该素材不再是该数据集成员，但素材记录与二进制仍保留（是否在素材库展示取决于其 `library_visible`）

#### Scenario: 多选批量移出
- **WHEN** 用户在数据集成员列表中多选若干成员并确认批量移出
- **THEN** 所选素材均不再是该数据集成员，素材文件本身仍保留

### Requirement: 允许无采集源的数据集
系统 SHALL 允许数据集的成员全部或部分来自导入等非素材库浏览路径；不得要求每个数据集都必须先有采集目录中的「源素材」。

#### Scenario: 仅含导入成员的数据集
- **WHEN** 某数据集的成员均为导入产生的非库可见素材
- **THEN** 数据集仍可正常列出成员、标注、发版与导出

### Requirement: 数据集反映成员数据来源
系统 SHALL 能提供数据集成员的来源汇总，覆盖至少：视频抽帧（含抽帧任务设置）、素材库上传图片、以及（若有）导入包；供工作区查看。发版时 MUST 将足以理解构成的来源摘要纳入版本快照（或可经由快照中的成员追溯到 Asset / 抽帧任务 / 导入记录）。

#### Scenario: 查看混合来源摘要
- **WHEN** 用户查看同时含抽帧成员与上传图片成员的数据集详情
- **THEN** 汇总中能区分抽帧来源（含源视频与抽帧设置及数量）与上传图片来源（及数量）

#### Scenario: 查看抽帧设置摘要
- **WHEN** 用户查看含有视频抽帧成员的数据集详情
- **THEN** 可获知至少「源视频 + 抽帧设置 + 来自该设置的帧数量」一类信息

#### Scenario: 发版后仍能知道当时来源构成
- **WHEN** 用户查看已发布版本的来源相关信息
- **THEN** 仍能获知该版本成员的来源摘要（含抽帧设置若适用），且不因之后工作区变更而改变

### Requirement: 成员划分字段
系统 SHALL 为每个数据集成员持久化划分字段，取值含 `train`、`val`、`test` 或 `unassigned`。工作区入集默认可为 `unassigned`；**产品主路径在发版时按比例随机写入 train/val/test**（见 dataset-versioning）。工作区 UI MUST NOT 将 `unassigned` 作为面向用户的划分选项或标签展示（避免迷惑）；划分结果以版本快照为准展示。
